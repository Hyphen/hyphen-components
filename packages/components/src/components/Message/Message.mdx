# Message

Message composes a single conversation row, including the sender's avatar, message body, metadata, and actions. It controls alignment and spacing while letting the caller choose the visible surface: a bubble, rich text, attachments, or custom content.

<Canvas of={Stories.Conversation} />

## Components

| Component | Description | Placement |
| --- | --- | --- |
| `Message` | The root row. `align="start"` (default) places a received message at the start; `align="end"` places a sent message at the end and moves the avatar to that side. Provides the alignment inherited by Header and Footer. | Inside the conversation or a `Message.Group`. |
| `Message.Avatar` | A non-shrinking slot for an image, initials, or another sender representation. Anchors to the bottom of the message surface and reserves space above the footer, including when footer content wraps or expands. It does not render an avatar image itself. | Beside `Message.Content`, inside `Message`. |
| `Message.Content` | Stacks the sender header, body, and footer with a small gap. Set width constraints here and supply the body or bubble styling yourself. It adds no default bubble background or padding. | Inside `Message`. |
| `Message.Header` | A row for the sender's name and identity metadata. Aligns its children to the message side by default. Supports Box props such as `gap`, `wrap`, and `alignItems`. | Before the body, inside `Message.Content`. |
| `Message.Footer` | A row for timestamps, delivery status, and actions such as Copy or Like. Metadata and wrapping actions follow the message side. Measures its height so the avatar stays clear of the footer. | Keep one Footer as the last child of `Message.Content`. |
| `Message.Group` | Stacks consecutive messages with a small gap. The caller decides which messages share a sender and when to repeat the avatar, header, or footer. | Around multiple `Message` rows. |

Every part accepts Box props and forwards its ref. Dot notation groups related parts; the same components are available as named exports: `MessageRoot`, `MessageAvatar`, `MessageContent`, `MessageHeader`, `MessageFooter`, and `MessageGroup`.

## Composition

```tsx
<Message.Group>
  <Message align="start">
    <Message.Avatar>
      <img src={sender.avatarUrl} alt={sender.name} width={32} height={32} />
    </Message.Avatar>
    <Message.Content maxWidth="80%">
      <Message.Header>{sender.name}</Message.Header>
      <Box background="secondary" radius="md" padding="xl">
        {message.text}
      </Box>
      <Message.Footer>{message.sentAtLabel}</Message.Footer>
    </Message.Content>
  </Message>
</Message.Group>
```

Message has no live-region role by itself. Put messages inside MessageScroller.Content to announce new rows, and give interactive actions accessible labels. Use Marker between rows or groups for dates and system events such as support joining or leaving.

## Start and end alignment

Set `align="start"` on received messages and `align="end"` on sent messages. The row, avatar side, sender name, and footer follow that choice. Use the same content composition on either side.

## Bottom-anchored avatars

The avatar aligns with the bottom of the message surface, above the footer and its gap. Footer sizing is observed so wrapped actions and expanded delivery details remain clear of the avatar. Expand the delivery details below to try it. Keep one footer as the last child of `Message.Content`; with no footer, the avatar aligns with the content's bottom edge.

## Header and footer slots

Use Header for the sender's name or other identity information. Footer holds timestamps, delivery status, and message actions. Actions are ordinary accessible buttons; the example's Like button toggles its pressed state.

<Canvas of={Stories.HeaderAndFooter} />

## Footer alignment and actions

Footer inherits the message side. An `align="end"` row keeps metadata and actions at the end even when a narrow viewport wraps them. Neither footer below has an explicit alignment override. Like and Save are interactive in both rows.

<Canvas of={Stories.FooterFollowsMessageSide} />

## Consecutive message groups

Use Group to stack consecutive messages from one sender with a smaller gap than the surrounding conversation. Reserve avatar space with an empty, equally sized Avatar on earlier messages, then show the avatar and footer on the last message. Group does not infer sender identity or hide repeated metadata; the caller controls those choices.
